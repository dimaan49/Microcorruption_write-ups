## Решение

Сначала пробежимся по инструкциям сначала файла командой `s`   
Также походу решения нам будет очень полезна команда `read`   
Она читает данные лежащие по адресу указанному в регистре   
То есть если r15 = 0x2490, то   
`read r15` выведет   
2490 some data ofbi nary code    
Далее разберем блок кода create_password   
```asm
mov	#0x2400, r15

mov.b	#0x64, 0x0(r15)
                      
mov.b	#0x3a, 0x1(r15)
                      
mov.b	#0x78, 0x2(r15)
                      
mov.b	#0x21, 0x3(r15)
                      
mov.b	#0x24, 0x4(r15)
                      
mov.b	#0x56, 0x5(r15)
                      
mov.b	#0x60, 0x6(r15)
                      
mov.b	#0x0, 0x7(r15)
                      
ret
```
Мнемоники внутри этого кода записывают байт (правый операнд) в ячейку по адресу (левый операнд)
Пример
mov.b   #0x64, 0x0(r15)
Записывает 0x64 в ячейку [r15+0]
r15 на протяжении всей этой функции имеет значени 0x2400, после нее
начиная с адреса 0x2400 будут записаны следующие байты:
d:x!$V'

| d | : | x | ! | $ | V | ` |
|---|---|---|---|---|---|---|
| 0x2400 | 0x2401 | 0x2402 | 0x2403 | 0x2404 | 0x2405 | 0x2406 |

Дальше идет вывод фразы
"Enter password to continue"
Адрес этой строки кладется в r15 (инструкция 4440)

Потом программа просит ввести строку, выполняя прерывание 0x10 в конце, все как обычно

I/O делает все через системное прерывание 0x10 (в реализации puts)

Далее идет самаяя важная функция а именно check_password, которая и проверит введенный нами пароль

Собственно сама функция
``` asm
44bc <check_password>

44bc:  0e43           clr	r14

44be:  0d4f           mov	r15, r13

44c0:  0d5e           add	r14, r13

44c2:  ee9d 0024      cmp.b	@r13, 0x2400(r14)

44c6:  0520           jnz	$+0xc <check_password+0x16>

44c8:  1e53           inc	r14

44ca:  3e92           cmp	#0x8, r14

44cc:  f823           jnz	$-0xe <check_password+0x2>

44ce:  1f43           mov	#0x1, r15

44d0:  3041           ret

44d2:  0f43           clr	r15

44d4:  3041           ret

```
### Справочная информация
| Регистр | Значение | Применение |
|  :---:  |   :---:  | :---       |
| r13     |  0       | Пользовательский пароль |
| r14     |  0       |  Счетчик, перебор символов |
| r15     |  0xx439c | Пользовательский пароль |

> @r14+0x2400 -- пароль из create_password (d:x!$V`)

### <a id = "steps_check_pass"> Шаги функции check_password </a>
1. Очищает регистр r14
2. Переносит значение из регистра r15 в r13 (0x439c)
3. Добавляем значение r14 к r13 (r13 = r13 + r14) 
4. cmp.b    @r13, 0x2400(r14) сравнивает значение по адресу @r13 с [r14+0x2400]
5. Если они не равны (в sr выставлен флаг zero), то прыжок на 44d2 (clr r15) и выход из функции
6. Если равны то увеличиваем r14 на 1 и сравниваем с 8
7. Если r14 равен 8, то пишем 1 в r15 и выходим
8. Если нет, то прыгаем на 44be , по сути на начло функции

    Таким образом будет увеличиваться r13    
( то есть происходит по сути смещение указателя, перебор строки)   
и в данном случае r14 это просто счетчик цикла for (int i = 0; i <=8 ; i++)

    Теперь когда мы разобрали функцию    
проверки пароля нужно понять что мы   
ждем на ее выходе (ну или можно было озадачиться этим ранее)

В общем код из main нам  в этом поможет

``` asm
4438 <main>

4438:  3150 9cff      add	#0xff9c, sp

443c:  b012 7e44      call	#0x447e <create_password>

4444:  b012 9445      call	#0x4594 <puts>

4458:  3f40 0345      mov	#0x4503 "Invalid password; try again.", r15

```

Можно сказать что нас интересует весь код,   
но и так ясно что если 
мы прошли задание то в r15 попадет     
Acces Granted!, а если нет, то Invalid password, try again.


get_password просто принимает наш ввод, create_password
создает пароль на стороне программы (в памяти устройства), это мы уже разобрали,
Но самое главное, что сразу после check_password стоит 
`tst r15`, она сравнивает r15 с 0, и выставляет флаги
А это две операции сразу после tst r15
```
jnz	$+0xc <main+0x2a>
                                                   
mov	#0x4503 "Invalid password; try again.", r15
```
Первая делает прыжок только если ZERO-flag не установлен ( то есть r15 не равен 0)     
А вторая кладет в r15 адрес строки, с уведомлением о проваленном задании,    
Мы задание хотим выполнить, а значит не попасть на строку 4458 (invalid password),   
**ЗНАЧИТ Нам просто необходимо выполнить прыжок командой ранее.**    
А значит в r15 не должен быть 0   

Вспоминаем check_password который одной операцией устанавливает #1 в r15 и сразу же выходит в main   
И обращаясь к [логике функции](#steps_check_pass) понимаем что мы должны иметь в r13 и r14+0x2400   
Одинаковые значения вплоть до момента, пока r14 не станет равным 8,    
После этого мы попадаем на jnz, который не срабатывает     
Так как zero-flag после проверку уже установлен (8=8, ZF = 1) и сразу попадаем на строку 
`mov #1, r15`
 А далее возврат в main, прыжок jnz на эту инструкцию

`4462:  3f40 2045      mov	#0x4520 "Access Granted!", r15`

Далее идет вывод и функция unlock_door которая завершает наше прохождение

3. Далее идет простая посимвольная проверка пароля.
